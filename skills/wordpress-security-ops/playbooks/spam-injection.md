# Spam Injection

Without BotBlocker, use database queries and host logs from `../references/without-botblocker.md`.

## Symptoms

- Spam posts, pages or comments.
- Hidden links in widgets, menus or options.
- Japanese keyword hack or doorway pages.
- Spam indexed by search engines.
- Comment or registration spam.

## First Checks

- [ ] `get-top-entities` for path and UA patterns.
- [ ] `get-login-attempts` for suspicious logins.
- [ ] `get-user-risk` for new or stale admins.
- [ ] Search posts, post meta, options and comments for links and scripts.
- [ ] Check cron and mu-plugins.
- [ ] Check theme files and widgets.
- [ ] Check search results with `site:`.

## Containment

- Preserve evidence and hashes.
- Disable comments or registration temporarily if spam is active.
- Block the confirmed source IP or ASN.
- Do not delete evidence before copying it.

## Eradication

- Remove spam posts, comments, options and widgets.
- Remove unknown users and cron hooks.
- Reinstall modified files.
- Rotate keys if admin access is suspected.
- Clean transients and caches.

## Recovery

- Restore from a pre-IOC backup if the scope is large.
- Request search engine removal only after the cause is fixed.
- Monitor for reinfection.
- 72-hour watch.

## Verification

- [ ] No spam in posts, comments, options or widgets.
- [ ] No new spam after 72 hours.
- [ ] Search console shows no security issue.
- [ ] Sitemap and robots are correct.

## Stop Conditions

- The site is used for phishing or malware distribution.
- The spam is generated by a compromised host or DNS.
- The client asks to hide the spam instead of removing it.
